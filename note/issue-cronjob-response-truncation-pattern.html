Issue: Cronjob Response Truncation Pattern

2026-06-08 18:30
##notebase-publish ##issue ##lesson-learned ##arch ##cronjob

問題模式

多個 cronjob (15:00 Dev Cycle 實作, 18:00 審查, 20:00 Global Macro, 21:00 部署) 都因 Response truncated 失敗

根本原因

  • 單次回應包含過多 write_file tool calls (每個大檔案 ~2-6KB)
  • 系統對單次回應總長度有硬性限制
  • 當工具調用序列過長時，輸出被強制截斷

失敗時間線

時間 任務 原因
15:00 Dev Cycle Phase 2 實作 一次寫 8+ 檔案被截斷
18:00 Dev Cycle Phase 3 審查 同上
20:00 Global Macro 報告 報告太長 + 寫入 notebase 被截斷
21:00 Dev Cycle Phase 4 部署 同上

解決策略 (驗證有效)

✅ 分微批次：每次回應只寫 1-2 個檔案，用戶確認後再下一批 ✅ 使用 execute_code 批量寫入：單次 tool call 內用 Python 寫多個檔案 ✅ 縮減 prompt 輸出要求：Telegram 只發摘要，完整內容存 notebase

行動項目

  • [x] 記錄此模式到 notebase
  • [ ] 重構 20:00 Global Macro prompt：縮減輸出格式，完整內容只存 notebase
  • [ ] 重構 21:00 部署 prompt：只做 build/deploy，總結存 notebase
  • [ ] 建立「大檔案批量寫入」工具函數
