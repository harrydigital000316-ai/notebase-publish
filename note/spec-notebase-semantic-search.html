SPEC: notebase-semantic-search — Local-First Semantic Search for notebase

🎯 Project Name & One-Liner

notebase-semantic-search — A lightweight semantic search server that embeds all notebase vault notes using local embeddings (via sentence-transformers/ONNX) and sqlite-vec, exposing a REST API for natural-language queries. Zero external dependencies, fully local, privacy-first.

🧠 Problem It Solves / Why Interesting

  • Current gap: notebase has fuzzy text search (rapidfuzz) but no semantic search — can't find "notes about AI safety" if they don't contain those exact words
  • notebase-publish search is client-side Fuse.js on pre-built JSON — same limitation, no semantic understanding
  • sqlite-vec provides a perfect local vector DB: single-file, SQL-native, no server, ~200KB extension
  • Integration opportunity: Reuse notebase's vault parser (vault.py), embed notes on write or batch, serve API for both CLI and web UI
  • Future RAG foundation: This becomes the retrieval layer for local LLM Q&A over the vault

🛠 Tech Stack

  • Python 3.10+ (matches notebase/notebase-insight)
  • sqlite-vec v0.1.10+ (vector search extension)
  • sentence-transformers or fastembed (ONNX embeddings, no PyTorch at runtime)
  • FastAPI (REST API, async, auto OpenAPI docs)
  • pydantic (request/response validation)
  • Typer (CLI for index/reindex/serve commands)
  • rich (CLI output)
  • notebase.vault (reused parser — import from sibling project)

✨ Core Features (4-5 bullets)

  1. Indexer: Walks vault, chunks notes (by heading/paragraph), computes embeddings, stores in sqlite-vec virtual table with metadata (note_id, title, tags, chunk_text, chunk_idx, created)
  2. REST API (/search, /search/hybrid, /health, /stats): Semantic KNN search with optional metadata filters (tags, date range), returns ranked results with snippets
  3. Hybrid Search: Combine sqlite-vec vector similarity + rapidfuzz text score (configurable weight) for best of both worlds
  4. Incremental Updates: Watch vault for changes (file mtime), re-embed only modified notes; reindex command for full rebuild
  5. CLI: notebase-semantic-search index, serve --port 8080, reindex, stats, config

🔗 Integration Points

  • Reads: notebase vault (~/dev_notes) — uses notebase's Vault/Store for parsing
  • Writes: sqlite-vec DB (~/.local/share/notebase-semantic-search/vectors.db)
  • Serves: REST API on localhost:8080 (configurable)
  • Future: notebase-publish search.html can call this API for semantic results
  • Future: notebase-insight can use semantic search for "related concepts" detection

📋 Implementation Notes

  • Embedding model: sentence-transformers/all-MiniLM-L6-v2 (384 dim, fast, good quality) or BAAI/bge-small-en-v1.5 (384 dim, better). Use ONNX via fastembed for zero-PyTorch runtime.
  • Chunking strategy: Split by markdown headings (##, ###), then by paragraphs. Max chunk ~500 tokens. Store chunk_idx for reconstruction.
  • sqlite-vec schema:
    CREATE VIRTUAL TABLE chunks USING vec0(
    embedding FLOAT[384],
    note_id TEXT,
    title TEXT,
    tags TEXT,           -- JSON array
    chunk_text TEXT,
    chunk_idx INTEGER,
    created TIMESTAMP,
    +partition_key=note_id
);
  • Distance metric: Cosine (default for normalized embeddings)
  • Hybrid scoring: score = alpha * (1 - vec_distance) + (1 - alpha) * text_score_normalized
  • Config file (~/.config/notebase-semantic-search/config.yaml):
    vault_path: "~/dev_notes"
db_path: "~/.local/share/notebase-semantic-search/vectors.db"
embedding_model: "BAAI/bge-small-en-v1.5"
chunk_size: 500
chunk_overlap: 50
hybrid_alpha: 0.7
api_host: "0.0.0.0"
api_port: 8080
